# 10 · 需求追踪矩阵

## 10.1 说明

本矩阵把《第 4 章功能描述拆分稿》的 **38 项功能**与原型页面、需求细化程度、确认表优先级对齐，用于发现"有需求无原型、有原型无需求、有功能无验收"的缺口。

状态口径：

- **详细**：需求文档有字段、规则、验收或流程描述。
- **较详细**：有功能点与设计说明，字段/验收不全。
- **大纲**：仅拆分稿的一句话"功能说的是啥/想怎么做"。
- **空**：需求文档只有章节标题。

## 10.4 缺口清单

### 有需求、无原型

- 设备映射关系评定
- 遥调能力评定
- 动态数据合理性评定
- 机房运行评估
- 电表运行评估
- 空调运行评估
- 电池健康度/衰减分析
- 能量运营监测/分析
- 收益测算
- 导出管理

### 有原型、需求未细化

- 供备电能力评估
- 实际收益评定
- 收益看板
- 电价设置
- 远程放电三页
- 削峰填谷三页
- 站址集合
- 机房管理/设备管理/查看设备
- 批量调试/查询性能/查询告警
- 用户/角色/平台日志

### 有功能、无验收标准

除 4.1.1 有 16 条验收、4.1.1 调整稿有 9 条验收外，其余模块均无验收标准。4.1.2 只有字段与流程描述，无验收条款。

### 有原型、无字段定义

原型主体是截图，无法从 HTML 提取字段级定义；需结合需求文档或 `.rp` 源文件。

### 有数据、无算法

遥调最优记录、动态数据最优结果、失真判据、收益公式、电池衰减模型、运行质量评分均未定义，见 [06 · 6.13](06-关键算法与接口口径.md#613-算法缺口清单)。

## 10.5 验收要点汇总

### 资源准确性（16 条，节选）

| # | 验收项 | 标准 |
| ---: | --- | --- |
| 1 | 对比来源设置生效 | 选"动环+现场"后只展示两来源字段与结论 |
| 2 | 多维查询准确 | 地市/区县/虚拟集合/结论/名称查询后全部页签刷新 |
| 3 | 站房ID批量查询 | 中英文逗号/空格/换行；无效 ID 不返回无关数据 |
| 4 | 来源展示清晰 | 切换来源后字段、列、结论同步变化 |
| 5 | 导入后结果更新 | 完成校验、入库、匹配、即时重算 |
| 6 | 导入异常提示 | 缺字段/格式错误/无法匹配给出原因与明细 |
| 7 | 关联规则正确 | FSU 按机房 ID，其他按设备编码 |
| 8 | 站房汇总准确 | 任一设备数量/属性不一致时体现差异 |
| 9 | 数量评估准确 | 五类设备不同来源数量对比正确 |
| 10 | 设备评估准确 | 能定位到具体设备与字段 |
| 11 | 结论与异常标识 | `-` 与 `/` 不混用 |
| 12 | 列表与浮窗 | 长字段可浮窗查看 |
| 13 | 自动更新 | 动环同步/导入后重算 |
| 14 | 导出一致 | 字段、顺序、页签一致，补 ID |
| 15 | 导出阈值 | 超过 1 万条拒绝并提示 |
| 16 | 权限控制 | 设置对比项默认仅超级管理员 |

### 性能质量（文档要求，未列为验收表）

- 基础/完全整治范围正确；
- 无标准设备不评估，全部无标准时提示；
- 采样窗口默认 0 点前后 30 分钟；
- 协议变更次日提示重评；
- 导出字段与列表一致，50 万条分 sheet。

### 接口质量（文档要求，未列为验收表）

- 5 分钟状态判定正确；
- 成功率 1 位小数，分母 0 显示 `-`；
- 可用性阈值 90%；
- 省/地市视角模块差异；
- 告警文案变量替换正确；
- 明细可下钻。

### 运营池（草案要求）

- 准入规则正确；
- 仅展示最近一次有效结果；
- 实际可放电时长可编辑、保存后刷新；
- 保存失败保留原值；
- 导入失败返回明细；
- 空值按规则显示 `-`。

## 10.6 版本演进与决策点

| 版本 | 关键决策 | 影响 |
| --- | --- | --- |
| v0.1 | 建立模板，资源质量评估 | 确定文档结构 |
| v0.2 | 接口质量即时总览 | 接口质量成为独立能力 |
| v0.3 | 增加性能/映射/协议/遥调/动态 | 数据质量 7 项成形 |
| v0.4 | 38 项功能拆分 | 形成功能清单 |
| v1.0 | 4.1.1.4 功能设计与验收多次调整 | 资源准确性固化 |
| v1.1 | 当前基线 | 仍需补齐 4.2/4.4–4.12 |

**需要尽早决策的 6 件事**：

1. 运营池准入以"基础整治合格"还是"性能质量合格"为准。
2. 运营池字段命名与菜单位置。
3. 接口质量一期范围（是否包含通道卡片、状态图、明细下钻）。
4. 数据质量"总体打分"是否本期建设、规则由谁维护。
5. 遥调/动态数据"最优记录"的算法规则。
6. 权限矩阵（角色 × 页面 × 按钮 × 数据范围）。

## 10.7 建议的下一步

1. 以本矩阵为 checklist，逐项补齐"空/大纲"需求。
2. 为每个模块补一页"字段 + 状态 + 接口 + 验收"。
3. 用 [06](06-关键算法与接口口径.md) 的伪代码与算法缺口清单，组织一次研发/产品评审。
4. 用 [05 · 5.8](05-数据模型与业务规则.md#58-已知冲突与待确认) 的冲突清单，形成决策记录（ADR）。
5. 原型补齐缺失页面后，重新导出并替换 `河北三期原型.zip`。
6. 建立代码仓库后，把本 Wiki 的模块编号与代码包结构一一对应。
