## 6.2 资源一致性判定

### 6.2.1 单设备结论

```text
function assessResourceConclusion(sourceResults, compareSources):
    # sourceResults: {动环: {...}|null, 综资: {...}|null, 现场: {...}|null}
    loaded = sources in compareSources where sourceResults[source] != null
    if loaded.size < compareSources.size:
        return "-"                      # 数据源未完全导入
    if all sources have no device:
        return "/"                      # 所有来源均无资源
    for field in [厂商, 型号, 监控模块型号, 软件版本号, ...]:
        values = distinct(field values from loaded sources)
        if values.size > 1:
            return "不一致"
    return "一致"
```

要点：

- `-` 与 `/` 的优先级：先判断来源是否齐全，再判断是否所有来源都无设备。
- 软件版本号为空时允许显示 `/`，且不影响合格结论（文档明确限定）。
- 属性对比展示为"现场 | 动环 | 是否一致"；只比两个来源时只展示两列。

### 6.2.2 数量分析结论

```text
function assessQuantityConclusion(counts, sources):
    # counts = {动环: int|null, 综资: int|null, 现场: int|null}
    loaded = sources with non-null count
    if loaded.size < sources.size: return "-"
    if all counts == 0:           return "/"
    if sources.size == 3:
        return "数据一致" if counts.动环 == counts.综资 == counts.现场
               else "数据不一致"
    if sources == [动环, 综资]:
        if 综资 < 动环: return "综资少于动环"
        if 综资 > 动环: return "综资多于动环"
        return "数据一致"
    if sources == [动环, 现场]:
        if 动环 < 现场: return "动环少于现场"
        if 动环 > 现场: return "动环多于现场"
        return "数据一致"
    if sources == [现场, 综资]:
        if 综资 < 现场: return "综资少于现场"
        if 综资 > 现场: return "综资多于现场"
        return "数据一致"
```

**差异口径**：`diff = 现场数量 - 动环数量`（文档明确）。当来源组合不含现场或动环时，差异列是否展示需产品确认。

### 6.2.3 站房汇总

```text
function assessStationSummary(deviceResults[5], sourcesComplete):
    if not sourcesComplete: return "-"
    if all devices have no resource: return "/"
    if all five devices: quantity == 一致 and info == 一致:
        return "一致"
    if any device: quantity == 不一致 or info == 不一致:
        return "不一致"
    return "-"
```

站房汇总的"数量对比/信息对比"是**五个子列**，每个子列独立显示一致/不一致/`-`/无设备。

## 6.3 性能质量整治判定

```text
function assessPerformance(standardSignals, sampledSignals, mode):
    # mode = 基础整治 | 完全整治
    if standardSignals is empty:
        return "-"                          # 无标准，不评估
    if no device:
        return "/"
    total    = count(standardSignals)
    actual   = count(signal in sampledSignals within sampleWindow)
    missing  = count(signal not sampled)
    distorted = count(signal sampled but invalid)
    if mode == 基础整治:
        ok = (actual > 0) and (distorted == 0)
    else:
        ok = (actual == total) and (distorted == 0)
    return {
        signal_total: total,
        signal_actual: actual,
        signal_missing: missing,
        signal_distorted: distorted,
        conclusion: ok ? "合格" : "不合格",
        signal_source: mode == 完全整治 ? source : null
    }
```

关键参数：

| 参数 | 默认 | 可配 |
| --- | --- | --- |
| 采样时间窗 | 凌晨 0 点前后 30 分钟 | 是 |
| 无标准设备 | 不评估，计入"无法评估" | — |
| 协议变更检测 | 每日凌晨 | — |

> 文档未给出"失真"的具体判据（阈值、上下限、突变率），需在协议库或算法侧补充。

## 6.4 映射完整性判定

```text
function assessPowerMapping(power):
    batteries = mappedBatteries(power)
    if batteries is null: return "-"
    if batteries.size == 0: return "映射不完整"
    return "映射完整"   # 文档未定义"部分映射"的判定

function assessMeterMapping(meter):
    loads = mappedLoads(meter)
    if loads is null: return "-"
    if loads.size == 0: return "映射不完整"
    return "映射完整"
```

输出同时包含：下挂锂电池数、下挂铅酸电池组数、下挂智能锂电池数、未下挂电池数；电表侧为已映射设备数、未映射设备数。

> "映射完整"的严格定义（是否要求所有电池/回路都挂接）文档未明确，当前按"至少有一条映射"的保守口径描述，需产品确认。

## 6.5 遥调能力判定

```text
function assessRemoteControl(records):
    # 只统计参与过遥调任务的记录
    valid = records where participated == true
    if valid is empty: return "-"
    # 文档要求"多次结果选最优一条"，但未给出排序规则
    best = selectBest(valid, rule=最优规则)
    if best.success == false:        return "遥调失败"
    if best.depth < requiredDepth:   return "遥调深度不足"
    return "遥调成功"
```

## 6.7 接口质量口径

### 6.7.1 状态

```text
function assessChannelStatus(lastCollectTime, now, collectionReturnedData):
    if lastCollectTime is null:                 return "-"
    if now - lastCollectTime > 5 minutes:       return "-"   # 无采集
    if collectionReturnedData == false:         return "中断"
    return "正常"
```

### 6.7.2 成功率

```text
function calcSuccessRate(successCount, totalCount):
    if totalCount == 0: return "-"
    return round(successCount / totalCount * 100, 1)  # 保留 1 位小数
```

### 6.7.3 可用性

```text
function calcAvailability(todaySuccessRate, currentStatus, everCalled):
    if not everCalled:                       return "-"
    if todaySuccessRate > 90 and currentStatus != "中断":
        return "可用"
    return "不可用"
```

### 6.7.4 其他指标

| 指标 | 口径 |
| --- | --- |
| 离线持续时长 | `now - lastOfflineStart`；在线 `-` |
| 当日离线次数 | 当日累计事件数，恢复在线不清零 |
| 并发情况 | 当前调用中 FSU 通道数 / 接入 FSU 通道总数 |
| 5 分钟聚合 | 当日 0 点至今按 5 分钟分桶 |
| 中断原因 | 浮窗展示，多个原因分别显示次数（原因分类规则未定义） |

## 6.10 权限与数据范围

```text
function filterByDataPermission(user, sites):
    scope = user.role.dataScope        # 省/地市/区县
    visible = sites where site.region in scope
    return visible

function canShowButton(user, button):
    return button.permission in user.role.buttonPermissions
```

要求：

- 无某地市权限时，连地市名称都不可见。

## 6.13 算法缺口清单

以下算法在仓库中只有目标描述，没有可执行定义：

1. 遥调"最优一条"的排序规则与遥调深度阈值。
2. 动态数据"最优结果"的选取规则，以及 8 类失真的具体判据。
3. 性能"失真"的判定阈值（越界、跳变、持续时长等）。
4. 接口中断原因分类规则。
5. 收益测算/实际收益的计算公式、电价时段与损耗口径。
6. 电池衰减模型与生命曲线拟合方法。
7. 供备电能力、机房运行、电表运行、空调运行的评分与阈值。
8. 数据质量总体打分规则（客户提出"可自定义评分规则"）。
9. 运营池"运营类型"的完整枚举。
10. 导入文件的字段级校验规则（长度、枚举、必填组合）。

建议在开发前以"算法说明书 + 样例数据 + 期望输出"的形式补齐，并转化为测试用例。
